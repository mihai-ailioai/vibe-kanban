A workspace is your task execution environment where you work with coding agents. Each workspace can include one or more repositories and supports multiple conversation sessions.

## What Happens When You Create a Workspace

Understanding what happens behind the scenes helps you work more effectively:

<Steps>
<Step title="Workspace mode determines how code is opened">
Vibe Kanban creates the workspace using the mode you selected:

- **`git_worktree` (recommended)** creates a managed git worktree on a new working branch
- **`in_place_git`** opens your existing git checkout in place
- **`in_place_directory`** opens a plain folder without Git operations
</Step>

<Step title="Working branch is created">
A new working branch is created when the mode supports it. In `git_worktree`, Vibe Kanban creates the branch from your target branch (for example `main`). The branch name is auto-generated from your task (for example `vk/abc123-add-login-page`).
</Step>

<Step title="Agent session starts">
A coding agent is initialised and ready to receive your instructions. The agent can read files, make changes, and run commands within your workspace.
</Step>

<Step title="Setup scripts run (if configured)">
If your repository has setup scripts configured (e.g., `npm install`), they run automatically to prepare the environment.
</Step>
</Steps>

<Info>
**Where do workspaces live?** `git_worktree` workspaces are created in a `.vibe-kanban-workspaces` directory (configurable in Settings → General → Workspace Directory). `in_place_git` and `in_place_directory` use the repo or folder you selected instead of creating a managed copy.
</Info>

## Compare Workspace Modes

Choose the mode that matches how you want to work with your code:

| Mode | Best for | What you select | What Vibe Kanban does |
| --- | --- | --- | --- |
| **`git_worktree`** | Most software tasks | One or more repositories and a target branch for each repo | Creates managed git worktrees and new working branches |
| **`in_place_git`** | Advanced Git workflows in existing checkouts | One or more existing repositories | Works directly in those repo folders without creating a separate repo copy |
| **`in_place_directory`** | Non-Git folders such as Unity projects | One folder | Opens the folder directly and hides unsupported Git actions |

<Tip>
Use `git_worktree` unless you have a specific reason to work in place. It gives you the clearest isolation and keeps your main checkout untouched.
</Tip>

## Creating a New Workspace

<Steps>
<Step title="Open the Create View">
  Click the **+** button at the top of the workspace sidebar, or use the command bar (`Cmd/Ctrl + K`) and select **New Workspace**.

  <Frame>
  <img style={{maxHeight: "300px"}} src="/images/workspaces-sidebar-create-button.png" alt="Workspace sidebar showing the plus button for creating new workspaces" />
  </Frame>
</Step>

<Step title="Select a Project">
  Choose a project from the **Project** dropdown in the right panel. Projects group related repositories together.

  <Frame>
  <img style={{maxHeight: "300px"}} src="/images/workspaces-select-project.png" alt="Project dropdown showing selected project" />
  </Frame>

  <Note>
  If you haven't created a project yet, see [Creating a New Project](#creating-a-new-project) below.
  </Note>
</Step>

<Step title="Choose a Workspace Mode">
  Select how you want the workspace to open your code:

  - **`git_worktree`** for the recommended default workflow
  - **`in_place_git`** when you intentionally want to work in existing git checkouts
  - **`in_place_directory`** when you want to work in a plain folder without Git
</Step>

<Step title="Select Repositories or a Folder">
  <Frame>
  <img style={{maxHeight: "350px"}} src="/images/workspaces-add-repo.png" alt="Repository selection showing selected repo with branch dropdown and list of available repositories" />
  </Frame>

  The inputs change based on the mode:

  - **`git_worktree`** - select one or more repositories to include
  - **`in_place_git`** - select one or more existing repositories to use in place
  - **`in_place_directory`** - select one folder to open directly

  For Git-backed modes, you can:

  - **Use recent repositories** - Click any repo from the list to add it
  - **Browse repos on disk** - Find repositories not in the recent list
  - **Create a new repo on disk** - Initialise a new git repository

  <Tip>
  You can add multiple repositories to a single workspace in Git-backed modes if your task spans multiple codebases. Each repository keeps its own git state.
  </Tip>
</Step>

<Step title="Set Target Branches">
  If you selected `git_worktree`, set the **target branch** for each repository. This is the branch your changes will eventually be merged into, such as `main` or `develop`.

  Click the branch dropdown next to each repository to change the target branch.

  <Info>
  **Target branch vs working branch - what's the difference?**

  - **Target branch** = Where your changes will eventually be merged, such as `main`. You set this.
  - **Working branch** = Where your changes are made, such as `vk/abc123-task-name`. Vibe Kanban creates this from the target branch in `git_worktree` mode.

  Your changes stay on the working branch and do not affect the target branch until you create and merge a pull request.
  </Info>
</Step>

<Step title="Describe Your Task">
  In the chat input at the bottom, describe what you want to accomplish. Be specific about:

  - What feature or fix you need
  - Any constraints or requirements
  - Files or areas of the codebase to focus on

  <Tip>
  Clear, detailed task descriptions help the agent understand your requirements and produce better results.
  </Tip>
</Step>

<Step title="Select an Agent">
  Choose which coding agent to use from the **Agent** dropdown. Available agents depend on your configuration.

  <Note>
  See [Agent Configurations](/settings/agent-configurations) for details on setting up different agents.
  </Note>
</Step>

<Step title="Create the Workspace">
  Click **Create** to start the workspace. The agent will begin working on your task immediately.
</Step>
</Steps>

## Creating a New Project

If you need to create a new project before setting up your workspace:

<Steps>
<Step title="Open the Project Dropdown">
  In the create workspace view, click the **Project** dropdown.

  <Frame>
  <img style={{maxHeight: "300px"}} src="/images/workspaces-project-dropdown.png" alt="Project dropdown showing Create new project option and list of existing projects" />
  </Frame>
</Step>

<Step title="Select Create New Project">
  Click **+ Create new project** at the top of the dropdown list.
</Step>

<Step title="Enter Project Details">
  <Frame>
  <img style={{maxHeight: "250px"}} src="/images/workspaces-create-project.png" alt="Create Project dialog with name field" />
  </Frame>

<Step title="Continue with Workspace Creation">
  Your new project is automatically selected. Continue by choosing a workspace mode and then selecting repositories or a folder.

After creating a project, you can configure additional settings like setup scripts, dev server scripts, and cleanup scripts in the project settings. See [Projects & Repositories](/settings/projects-repositories) for more details.

## Workspace Settings

Once a workspace is created, you can configure additional settings:

### Working Branch

`git_worktree` workspaces automatically create a working branch for your changes. You can view and change this in the **Git** section of the details sidebar when the workspace mode supports Git.

### Dev Server

If your project has a dev server script configured, you can start it using:
- The **Play** icon (<Icon icon="play" />) in the context bar
- The command bar: `Cmd/Ctrl + K` → **Start Dev Server**

<Note>
Configure dev server scripts in your project settings. See [Projects & Repositories](/settings/projects-repositories) for setup instructions.
</Note>

### Workspace Notes

Use the **Notes** section in the details sidebar to document important information about the workspace - requirements, decisions, or anything you want to remember.

## Duplicating a Workspace

To create a copy of an existing workspace:

1. Open the command bar (`Cmd/Ctrl + K`)
2. Go to **Workspace Actions**
3. Select **Duplicate Workspace**

The duplicate includes the same repositories and branch configuration but starts with a fresh conversation.

## Archiving Workspaces

When you're done with a workspace, archive it to keep your workspace list clean:

**From the navbar:**
- Click the **Archive** button (<Icon icon="box-archive" />) in the top left of the navbar

**From the command bar:**
1. Press `Cmd/Ctrl + K`
2. Go to **Workspace Actions** → **Archive**

Archived workspaces can be viewed by clicking **View Archive** at the bottom of the sidebar.

<Tip>
Use the **Pin** feature to keep important active workspaces at the top of your list.
</Tip>

## Troubleshooting

<AccordionGroup>
<Accordion title="I can't see my repository in the list">
**Possible causes:**
- The repository hasn't been added to a project yet
- You selected a Git-backed mode, but the folder is not a git repository
- The path isn't accessible

**Solutions:**
1. Click **Browse repos on disk** to manually locate the repository
2. Ensure the folder contains a `.git` directory if you are using `git_worktree` or `in_place_git`
3. If you want to work in a plain folder, switch to `in_place_directory`
4. Check that Vibe Kanban has permission to access the folder
</Accordion>

<Accordion title="Workspace creation fails">
**Possible causes:**
- `git_worktree` setup failed because Git could not create the workspace or branch
- The selected repo or folder is not valid for the mode you chose
- Disk space issues

**Solutions:**
1. For `git_worktree`, commit or stash conflicting changes in the original repository and try again
2. Check that you selected repositories for Git-backed modes or a folder for `in_place_directory`
3. Try a different target branch if the failure is branch-related
4. Check available disk space, especially if you are creating managed worktrees
</Accordion>

<Accordion title="Agent doesn't start after creating workspace">
**Possible causes:**
- Agent isn't installed or configured
- API key issues
- Network connectivity problems

**Solutions:**
1. Check that your agent (e.g., Claude Code) is installed: run the CLI command manually in terminal
2. Verify API keys are configured in Settings → Agents
3. Check your internet connection
</Accordion>

<Accordion title="Setup script fails">
**Possible causes:**
- Script has errors
- Missing dependencies
- Wrong working directory

**Solutions:**
1. Test the script manually in terminal first
2. Check the Logs panel for error messages
3. Ensure paths in the script are relative to the repository root
</Accordion>
</AccordionGroup>
